Overview

Challenge Abstract

Muscle architecture parameters such as pennation angle (PA), fascicle length (FL), and muscle thickness (MT) are fundamental descriptors of skeletal muscle structure and function. These parameters are widely used in biomechanics, sports science, and clinical research to study muscle mechanics and adaptations to training.

Ultrasound imaging provides a non-invasive method to assess muscle architecture in vivo. However, current analysis methods often rely on manual or semi-automated annotation of fascicles and aponeuroses, which is time-consuming and prone to inter-observer variability.

Recent advances in computer vision and machine learning, particularly deep learning, have demonstrated strong potential for automated analysis of ultrasound images. Nevertheless, progress in this field is limited by the lack of standardized benchmark datasets and evaluation protocols.

The UMUD Muscle Architecture in Ultrasound Data Challenge aims to establish an open benchmark for automated extraction of muscle architecture parameters from ultrasound images. Participants will develop algorithms to estimate pennation angle, fascicle length, and muscle thickness from ultrasound images and will be evaluated on a test dataset with expert-annotated reference measurements.

The challenge provides a standardized dataset and evaluation framework to enable transparent comparison of algorithms and accelerate the development of reliable automated muscle architecture analysis tools.

Keywords: Ultrasound, Muscle Architecture, Pennation Angle, Fascicle length, Muscle thickness, Deep learning, Computer Vision, Biomechanics

Goal of the Competition

The goal of this competition is to build algorithms that can accurately estimate three key muscle architecture variables from ultrasound images:

  • Pennation Angle (PA): angle between muscle fascicles and the aponeurosis (degrees)

  • Fascicle Length (FL): length of muscle fascicles (millimetres)

  • Muscle Thickness (MT): distance between superficial and deep aponeuroses (millimetres)

Participants must predict these three values for each ultrasound image in the test dataset.

Submissions will be ranked using the UMUD Score, a composite metric that evaluates prediction accuracy across all three variables.

Novelty of the Challenge

The UMUD challenge represents one of the first open benchmarks for automated muscle architecture estimation from ultrasound images.

Key novel aspects include:

  • A public dataset with standardized architecture measurements

  • Evaluation across three physiologically meaningful parameters

  • A multi-metric evaluation framework capturing both accuracy and agreement with expert measurements

  • Inclusion of both deep learning and classical image processing approaches

The challenge aims to promote reproducibility and transparency in musculoskeletal ultrasound analysis

Why This Challenge Matters

Reliable automated analysis of muscle architecture would enable:

  • Large-scale studies of muscle adaptation in sports and health research

  • Standardized measurements across laboratories and clinical centers

  • Faster analysis pipelines for ultrasound imaging datasets

  • Open benchmarking of algorithms for musculoskeletal ultrasound analysis

Evaluation

Submissions are evaluated using the UMUD Score, which measures prediction error across all three architecture variables.

The score is based on a normalized mean absolute error (MAE) across:

  • Pennation Angle (PA)

  • Fascicle Length (FL)

  • Muscle Thickness (MT)

Errors for each variable are normalized by predefined tolerance values to ensure comparable influence despite different units and scales. Lower scores indicate better performance.

Reproducibility, FAIRness, and Open-Source Eligibility Check

The Kaggle leaderboard will be ranked using the official UMUD Score. However, to be eligible for the final official top-3 positions, prize consideration, and inclusion as a formally ranked winning method, teams must additionally satisfy the following software-sharing and reproducibility requirements:

Eligibility requirements for the top leaderboard entries

After the competition deadline, the teams provisionally placed 1st, 2nd, and 3rd on the private leaderboard will be asked to provide a public code repository for their final submission. The repository must satisfy all of the following conditions:

  1. Open source
    The code must be released under an OSI-compatible open-source license and be publicly accessible. ⚠️ Code without a license will not be considered.

  2. FAIR research software
    The repository must meet the FAIR software requirements, assessed using the FAIR Software Checklist (or equivalent FAIR software checker specified by the organizers). At minimum, the repository must be findable, accessible, and reusable through public hosting, clear licensing, documentation, and software metadata.

  3. Reproducible execution
    The method must be reproducible by the organizers from the provided repository using one of the following:

    • a jupyter notebook
    • a python/matlab script
    • an installable Python/Matlab package, or
    • a complete installer

⚠️ In case of single scripts, make sure that the environment requirements are described and the code is reusable and inter-operable (e.g., requirements.txt, environment.yml, or Docker configuration). Submissions in other languages than python/matlab are welcome as well.

  1. Documentation
    The repository must include sufficient instructions to reproduce inference on the challenge data, including dependency specification, installation steps, and execution commands.

Compliance review

The organizers will review these requirements for the provisional top-3 entries after the leaderboard closes. If a team fails the FAIR, open-source, or reproducibility check, that team will become ineligible for the final winning positions.

In that case, the next highest-ranked eligible team will move up. For example:

  • if the provisional 3rd-place team fails compliance, the provisional 4th-place team becomes the final 3rd-place team;

  • if the provisional 2nd-place team fails compliance, the provisional 3rd-place eligible team becomes final 2nd, and so on.

Scope of the compliance check

This FAIR/open-source/reproducibility review is applied to the top three provisional leaderboard entries only. The numerical Kaggle leaderboard score itself is unchanged.

Authors will be notified with a decision three weeks after challenge deadline.

What Participants Need to Do

Participants in the UMUD Muscle Architecture in Ultrasound Data Challenge are asked to develop an algorithm that can automatically estimate muscle architecture parameters from ultrasound images.

⚠️ Classic computer vision as well as deep learning based approaches are welcome.

Task Overview

For each ultrasound image in the dataset, participants must predict the following parameters:

Pennation Angle (PA)

The angle between the muscle fascicle and the deep aponeurosis, measured in degrees (yellow).

Fascicle Length (FL)

The length of the muscle fascicle between the superficial and deep aponeuroses, measured in millimetres (green).

Muscle Thickness (MT)

The perpendicular distance between the superficial and deep aponeuroses, measured in millimetres (pink).

Participants may use any algorithmic approach to estimate these parameters. This includes, but is not limited to:

  • deep learning methods

  • classical image processing pipelines

  • hybrid approaches combining both techniques

The algorithm should be able to extract the relevant structural information from the ultrasound image and produce accurate numerical estimates for PA, FL, and MT. ⚠️ The figure above illustrates typical manual annotation, but does not restrict any developed algorithm to the same output.

Input Data

The input to the algorithm is a single ultrasound image showing a region of skeletal muscle. Nonetheless, the test images include parts from video sequences (5 images in a row). This can be used to evaluate the temporal stability of the developed algorithm.

Each image contains visible structural features such as: superficial aponeurosis, deep aponeurosis, muscle fascicle fragments.
These structures form the basis for estimating the architecture parameters.

Expected Output

For each image in the test dataset, the algorithm must output predicted values for the three architecture parameters.

The required submission format is a CSV file with the following columns:

image_id pa_deg fl_mm mt_mm
image_00001 15.2 78.5 19.1
image_00002 13.7 81.3 18.4

Where:

  • image_id corresponds to the identifier of the ultrasound image

  • pa_deg is the predicted pennation angle in degrees

  • fl_mm is the predicted fascicle length in millimetres

  • mt_mm is the predicted muscle thickness in millimetres

Each image in the test set must appear exactly once in the submission file.

Training Constraints

Participants are free to design their algorithms using any approach that complies with the competition rules.

Allowed resources include: the provided training data, publicly available datasets (i.e., those indexed in UMUD, publicly available pretrained models.

If additional data or pretrained models are used, they must be clearly documented in the final method description.

Submission Process

Participants generate predictions for the test dataset and submit them through the Kaggle competition interface. Multiple submissions are allowed during the competition period. The submission with the best leaderboard score determines the participant's provisional ranking.
